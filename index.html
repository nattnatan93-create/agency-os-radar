Daily open-source discoveries for a one-person AI software agency

Start Here (plain English)

The problem: a one-person agency ships software with AI helpers, but clients only trust apps where (1) the tools the AI used are themselves safe and current, (2) every machine-checked claim comes with a real, dated report, and (3) agents don't leak passwords and API keys into code. "It works on my machine" is not production-ready; "here is the scan report from today" is.

The solution in today's radar: five fresh, verified finds. wshobson/agents is a big library of ready-made expert instructions you can drop into your AI coding IDE. agent-fleet-o is a self-hosted mission-control for agent teams with human-approval gates. Titus is a fast secret scanner that turns "no leaked keys" into a machine-generated report. mcp-accessibility-scanner lets your AI agent audit websites for accessibility failures (WCAG) with real keyboard tests. shadcn-admin is a free, MIT-licensed admin dashboard you own component-by-component — a reusable component for every future business web app.

The Production-Readiness Gap

The criticism: "AI-built apps aren't production-ready" is an evidence problem. Claims like "no secrets in the code", "the dashboard works", or "the agent followed best practices" are worthless unless a tool produced them — with a date, a format, and a pass/fail result your gate engine can read.

Today's answer: Titus produces SARIF/JSON secret-scan reports from your whole repo and git history; mcp-accessibility-scanner produces per-page WCAG violation reports from real browser sessions; wshobson/agents replaces vague "the agent knows testing patterns" hopes with reviewed, versioned instruction files; shadcn-admin replaces "the AI will design a consistent dashboard" with components you read and own before shipping.

Why this maps to Agency OS: your governance demands VERIFIED evidence before a gate advances. Today's tools are external evidence producers your gate engine can consume. None of them replaces the gate engine or project-state.json — they feed it.

1. wshobson/agents — 41K-star multi-harness plugin marketplace for AI coding IDEs TEST NOW

  • Link: github.com/wshobson/agents
  • What it does (simple English): a huge, curated library of "plugins" — agents, skills, and commands written as plain Markdown — that install into Claude Code, Codex CLI, Cursor, OpenCode, GitHub Copilot, Google Antigravity, and Pi. Instead of re-explaining to your IDE how to do code review, testing, or debugging, you install a reviewed instruction pack.
  • What changed recently and when: it crossed into GitHub Trending's top 15 on Oct 21, 2026 (~41,300 stars at the time); repo shows ~41,249 stars with +93/day velocity and a last update of Oct 19, 2026. Current scale per its README analyses: 94 plugins, 202 agents, 185 skills, 105 commands. (VERIFIED from repo/trending coverage this week.)
  • Why it matters to a vibe coder: this is the "write expertise once, use it in every IDE" layer. You switch between AI IDEs; your standards shouldn't depend on which one is open. Notably it includes a block-no-verify plugin whose hook rejects git commit --no-verify — exactly the anti-gate-bypass pattern Agency OS cares about.
  • License & costs: MIT (VERIFIED from repo license). External plugins have their own licenses — check each. Free; no subscription. Some plugin content may reference paid model features.
  • Windows & install: plain Markdown skills — OS-agnostic. Install per skill via GitHub CLI (gh skill install wshobson/agents <skill>) or npx skills add, or clone into your IDE's skills folder. Always read a skill's full text before installing — a skill is executable influence over your agent.
  • Agency OS fit: DEVELOPMENT stage (expert patterns for the dev agent) and REUSABLE_COMPONENT stage (a model for packaging your own standards as versioned, reviewed skills). Compatibility: plausible — skill files are plain Markdown; untested with your orchestrator/gate engine.
  • Evidence/output: installed skills are reviewable text files — you know exactly what instructions your agent received.
  • Limitations/risks/human review: one independent analysis calls it "a well-executed personal catalog with great visibility" — most plugins come from one author, so treat quality as varying; review every skill before loading; plugin content can drift from your tool versions.
  • Verdict: TEST NOW — zero-cost, zero-risk to try one skill today (start with block-no-verify).

3. Titus — high-performance secrets scanner from Praetorian (NoseyParker successor) TEST NOW

  • Link: github.com/praetorian-inc/titus
  • What it does (simple English): scans code, directories, git history, GitHub/GitLab repos, and Docker images for leaked credentials — API keys, tokens, passwords — using 487 detection rules. Every finding gets a 0–100 score and severity tier. Reports come out as human-readable text, JSON, or SARIF (the format GitHub CI understands).
  • What changed recently and when: Titus is the official replacement for the now-archived NoseyParker (per HackTricks' tooling index, verified Oct 2026), with active commits over the past year and a CI workflow on main; it's currently surfacing in security-tooling coverage this month. Specific release dates were not individually verified today.
  • Why it matters to a vibe coder: AI agents generate code fast — one hallucinated config file with a real-looking key can burn a client. Titus gives you a dated, machine-generated "no leaked secrets" artifact for every project, and scanning git history catches keys deleted from files but still buried in old commits.
  • License & costs: Apache 2.0 (VERIFIED from repo LICENSE; rules derived from Apache-2.0-licensed NoseyParker and Kingfisher). Free and offline-capable — detection runs with no external API by default. (Related market note: Gitleaks is now frozen — security patches only — and its original author's successor Betterleaks is at v2.0.0-rc.3 as of Oct 19, 2026.)
  • Windows & install: Go binary (Go 1.27+); prebuilt binaries from the official Releases page, or build with make build. Pure-Go fallback exists for platforms without Hyperscan/Vectorscan, so Windows is supported. No daemon, no subscription.
  • Agency OS fit: SECURITY stage (secrets) — security agent's scanner, and pre-commit/pre-push check complement to your precommit_check.py. Compatibility: plausible — SARIF/JSON output is gate-engine friendly; untested with your scripts.
  • Evidence/output: a datastore plus reports: titus report (human), --format json, --format sarif for CI.
  • Limitations/risks/human review: --validate (live credential verification) sends candidate secrets to provider APIs — never run it on client credentials without explicit approval; scanning public repos you don't own may raise legal/authorization questions; findings need triage — score ≠ confirmed leak.
  • Verdict: TEST NOW — single binary, offline, free, immediate Agency OS evidence value.

Test Today: Titus — offline secret scan on Windows (~30–45 min)

  • Why this one: single prebuilt binary, Apache 2.0, runs offline by default, no subscription, no API keys, and it produces exactly the evidence type your SECURITY gate wants (a dated scan report).
  • Prerequisites: a Windows PC; nothing else for the prebuilt binary (Go 1.27+ only if you build from source).
  • Official installation steps: download the Windows binary from the official GitHub Releases page only (never third-party mirrors); verify the checksum if the release provides one; alternatively build from source with make build per the README.
  • Practical test: (1) create a scratch folder (not a client project) and plant 3 obviously fake keys — e.g., a dummy AWS-style key, a fake GitHub token pattern, a fake Slack token; (2) run titus scan path\to\scratch; (3) run titus report --format json and titus report --format sarif; (4) make it a git repo, commit a fake key, delete the file, commit again, then titus scan --git path\to\repo — the "deleted" key should still be found in history.
  • Expected results: findings with rule name, score 0–100, and severity; JSON and SARIF files you can store as dated evidence. The git-history step should demonstrate that deleting a file does not delete a leak — the single most important lesson for agent-driven commits.
  • Safety precautions: use only fake keys in the scratch folder; do NOT run --validate (it contacts provider APIs); don't scan public repos you have no authorization to test; download only from the official repo; keep the binary out of client repos (run it from a tools directory).

Agency OS Integration Proposal: Titus SARIF reports as SECURITY-gate evidence

  • Problem solved: your SECURITY stage covers secrets, but today "no secrets committed" is an agent's claim unless a scanner produced a report. AI agents commit fast and often; a machine-checked secrets artifact makes the claim VERIFIED.
  • Exact workflow/agent it improves: the security agent's secrets check, complementing (not replacing) precommit_check.py and prepush_release_check.ps1.
  • Where in the lifecycle: SECURITY stage — run on every entry to SECURITY; also run the git-history scan at RELEASE as a final pre-publish check.
  • Inputs: the project repo path; the Titus binary; no network needed (offline detection). For public-repo or Docker-image scans, human authorization first.
  • Outputs: a dated SARIF/JSON report stored with the project, referenced from project-state.json as VERIFIED evidence: rule, score, severity, file, line.
  • How results are validated: the report is generated by the external tool, not authored by an agent; the security agent may attach and summarize it, never substitute its own verdict; zero findings = clean only if the report file exists and covers the full repo + history.
  • What happens on failure: any high-severity finding blocks SECURITY advancement → secrets are rotated/removed (history rewrite or key rotation is the only real fix) → rescan. A waiver (e.g., a flagged test fixture) is a governance decision → human approval required. This adds an evidence type to your existing gate engine — no replacement of the gate engine or governance is proposed.
  • Blocks a gate or needs human approval? Rule-based gate-blocking on findings; human approval for waivers, any use of --validate, and any scan of third-party assets.
  • Smallest safe experiment: today's scratch-folder test above. If the SARIF artifact looks good, wire one line into prepush_release_check.ps1 that runs Titus and fails on exit code — nothing more until proven on a real project.

Daily Learning: secrets in git history

  • Concept (simple English): git keeps every version of every file it ever committed. Deleting a file with a password in it, and committing the deletion, removes it from the latest version — but the password is still in the repository's history, and anyone who clones it can find it. The only real fix is rotating the credential; cleaning history is a bonus, not a cure.
  • How an AI agent might get it wrong: the agent notices a committed secret, deletes the file (or the line), commits "removed secret," and reports the issue resolved — believing deletion equals remediation. Or it "verifies" safety by checking the current files only, never the history.
  • How you recognize the failure: a remediation report that mentions deleting code but not rotating the key; a "clean" claim based only on a working-tree scan; the credential never revoked at its provider.
  • Which tool/test detects it: Titus — titus scan --git parses full git history and reports the "deleted" secret; that failing report is exactly the gate evidence that turns the agent's "resolved" claim back into BLOCKED until the key is rotated.
