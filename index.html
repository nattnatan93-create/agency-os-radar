Five Discoveries (verified Nov 10, 2026)

  • 1. Zeroshot TEST NOW — github.com/the-open-engine/zeroshot
    • What it does: a multi-agent orchestration engine that keeps coding agents from grading their own work. One agent implements, a different agent reviews, tests must pass, and both must approve before a PR is created; CI must pass before merge.
    • What changed recently: release v13.1.0 published today (Nov 10, 04:51 UTC); latest commit today. This is an update to an established, fast-moving project, not a new project.
    • Why it matters to a vibe coder: it mechanizes exactly the discipline a solo agency needs — no self-review, evidence before merge.
    • License (verified from LICENSE file): MIT.
    • Costs: free software; real cost is your existing Claude Code / Codex model subscription. No external service required.
    • Windows: installs via npm (npm install -g @the-open-engine-company/zeroshot); the repo's own CI includes a native Windows test lane (verified from a commit message). Plausible Windows support, untested here.
    • Agency OS fit: supports the QA stage and the dev agent — author/reviewer separation. Evidence output: reviewer verdicts plus test pass/fail per run. Feeds gate_engine.py; compatibility plausible, untested.
    • Limitations & human review: fast release cadence (pin the version); a reviewer agent can still be wrong — human review stays mandatory at gates; verdict TEST NOW.

Agency OS Integration Proposal: Zeroshot as the QA-stage author/reviewer separation

  • Problem solved: today the dev agent's QA evidence rests on prompts; nothing mechanistically prevents an agent from grading its own work.
  • Workflow/agent improved: the orchestrator's DEVELOPMENT → QA loop — dev agent implements, a second agent reviews, tests gate both.
  • Lifecycle point: DEVELOPMENT and QA, feeding the SECURITY transition.
  • Inputs and outputs: spec from SPECIFICATION plus tests in; independent reviewer verdicts and test pass/fail evidence out, per run.

  • Gate or human approval: it feeds existing gates and replaces nothing (gate_engine.py, advance_gate.ps1 unchanged). Human approval still required at CEO_REVIEW, scope changes, waivers and release.

Daily Learning: the self-grading problem (author/reviewer separation)

  • Concept (simple English): an AI agent that wrote code tends to approve it. The control is structural: a different agent reviews, and tests written from the spec (not from the code) must pass before anything advances.
  • How an AI agent might get it wrong: it writes tests after the code that merely mirror the implementation, or produces a "review" that restates the diff without criticizing anything, then declares the work done.
  • How you recognize the failure: tests that never failed once; review notes that only summarize; zero rejected drafts in the run history.
  • What detects it: zeroshot's author/reviewer separation plus your precommit_check.py; under Agency OS rules the gate engine rejects a QA transition whose evidence is UNVERIFIED.
