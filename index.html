The Production-Readiness Gap

The criticism: "AI-built apps aren't production-ready" is usually an evidence problem. An agent saying "no known vulnerabilities" or "the app works" is a claim. Production-ready means a scanner report with dates and findings, a test run against the real app, and an audit trail of what agents did.

Today's answer: Trivy and OSV-Scanner turn dependency/config security into machine-readable reports; Playwright's WebMCP support extends proven browser testing to the AI-tool layer; Orchestrator.inc and Orca turn "multiple agents working on one project" into a supervised, trackable workflow with branches, PRs, CI and review state attached.

Why this maps to Agency OS: your governance already demands VERIFIED evidence before a gate advances and human approval for release. Today's tools are external evidence producers — scanners and test runners whose output your gate engine can consume. None of them replace your governance; they feed it.

  • Link: github.com/google/osv-scanner · v2.7.0 release
  • What it does (simple English): scans your lockfiles and SBOMs and checks every dependency against OSV — the open, Google-backed database of known open-source vulnerabilities — so "is this package safe to use?" gets a data-backed answer.
  • What changed recently and when: v2.7.0 released Oct 12, 2026 (VERIFIED from the Releases page, signed release): package URLs (purl) in JSON output, vulnerability severity/rating in CycloneDX output, the Dart package-config extractor enabled by default, better Maven resolution, Bitnami SPDX SBOM scanning, and offline-mode fixes (no network-required plugins when scanning offline).
  • Why it matters to a vibe coder: agents love adding packages. OSV-Scanner is the cheap, automated check that turns "the agent added 12 dependencies" into a dated list of which ones carry known CVEs.
  • License & costs: Apache-2.0 (VERIFIED from the LICENSE file). Free, no subscription; queries the free public OSV API (or offline databases) — no paid account needed.
  • Windows & install: Go-based single binary; Windows binaries distributed on the Releases page (check the exact asset name there). No special hardware.
  • Agency OS fit: SECURITY stage (dependency auditing) and DEVELOPMENT pre-commit checks alongside your precommit_check.py. Compatibility: plausible — JSON output is gate-engine friendly; untested with your scripts.

  • Limitations/risks/human review: only as good as the OSV data and your lockfiles (unpinned deps are harder to judge); severity ≠ exploitability — humans decide what actually blocks a release.

Daily Learning: certificate trust chains (why a CA compromise is everyone's problem)

  • Concept (simple English): when your app talks HTTPS, it doesn't verify "the server is who it says it is" by itself — it trusts a short chain: the server's certificate, signed by an intermediate authority, signed by a root authority your operating system already trusts. If a thief steals an intermediate authority's private key, they can forge certificates your machine will happily accept as genuine. Today's Trivy v0.76.1 exists precisely because of such an incident (the eMudhra intermediate CA key compromise, mitigated via Go 1.27.3 and updated trust stores, tracked as CVE-2026-111943).
  • How an AI agent might get it wrong: the agent says "all HTTPS connections verified, no vulnerabilities" because the code makes HTTPS calls — but the trust store is outdated and still trusts the compromised chain; or it patches app code while ignoring the runtime/trust-store update that the CVE is actually about.
  • How you recognize the failure: the security evidence contains no line item for runtime/toolchain versions or trust-store freshness; "secure" claims rest on protocol use rather than on a dated scan of the actual environment.
  • Which tool/test detects it: Trivy v0.76.1 — scanning with an up-to-date scanner on an up-to-date runtime is exactly how CVE-2026-111943-class issues surface; its report shows which components (binaries, images, trust stores) need the update. Human review of the scanner's own version remains mandatory — as today proved, scanners need patching too.
