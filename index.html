Start Here (plain English)

The problem: a one-person AI agency needs its coding agent to behave like a disciplined software team — ask what the client really needs before building, write the spec down, plan the work, test first, and review everything — not a code-spitting chatbot that improvises. Stitching those habits together by hand, every day, is exactly what a solo vibe coder has no time for.

The solution in today's radar: obra/superpowers is a free, MIT-licensed methodology, delivered as skills, that plugs into the coding agent you already use (Claude Code, Cursor, Codex CLI, OpenCode, and many more). Once installed, your agent automatically follows one connected workflow: brainstorm the requirement → get your sign-off → isolate a git worktree → write a task-by-task plan → build with subagents under strict test-first rules → review each task → finish the branch with a human merge decision. It works end-to-end like a mini software factory — and today it shipped a fresh release (v7.0.1, Oct 21, 2026) plus repo commits on Oct 20, putting it inside the 7-day activity window.

Why It Fits Agency OS

  • No invented facts: verification-before-completion makes the agent prove it's fixed before declaring success — the same VERIFIED-before-advancing rule Agency OS enforces.
  • Evidence before advancing: TDD skill deletes code written before tests; code review blocks critical issues — external, checkable evidence, not claims.
  • Human approval points built in: design sign-off before planning; merge/PR/keep/discard decision at branch finish — matching Agency OS's human-approval rule for scope and release.
  • Isolation: git worktrees keep every change on a verified-baseline branch, so nothing touches main without evidence.
  • Complements, never replaces: Superpowers produces the artifacts; gate_engine.py stays the authority over whether a gate advances. Agency OS compatibility: plausible — untested until you run it alongside your scripts.

Limitations, Risks & Human Review

  • Telemetry: by default, an optional visual-companion logo is loaded from the project's website, including your Superpowers version (nothing about your project/prompt, per the README). Disable with SUPERPOWERS_DISABLE_TELEMETRY — worth doing for client work.
  • Model costs: subagent-driven development spawns fresh agents per task — thorough but token-hungry; executing-plans is the cheaper inline mode.
  • Autonomy risk: the README says sessions can run autonomously for a couple of hours — run in a scratch repo with scoped permissions first; never grant unrestricted computer access; keep human approval for commercial decisions and anything touching client repos.
  • Windows: hook spawning has Windows-specific fixes in the repo, but plugin behavior on Windows is untested here — verify on a scratch project before client use.
  • Discipline depends on the model: skills are instructions, not hard enforcement — a weak model can still skip them; that's why gate_engine.py stays in charge.

Agency OS Integration Proposal: Superpowers as the DEVELOPMENT→QA evidence producer

  • Problem solved: the dev and QA agents currently rely on prompts to behave well; Agency OS has no enforced plan-artifact + test-first evidence chain from the coding IDE itself.
  • Exact workflow/agent it improves: the dev agent's implementation loop and the QA agent's unit-test evidence — feeding, never replacing, gate_engine.py, precommit_check.py, and prepush_release_check.ps1.
  • Where in the lifecycle: SPECIFICATION (approved design doc) → DEVELOPMENT (plan file, worktree) → QA (TDD test evidence, review report).
  • Inputs: your feature request; existing project files (brainstorming reads them first, per v7.0.1).
  • Outputs: design document, plan file with exact file paths, per-task commits with RED→GREEN tests, severity-ranked review report, merge decision record.
  • How results are validated: a task counts as done only if the failing-test commit, passing-test commit, and review report exist in the repo — artifacts, not claims. A SUPERPOWERS-sourced claim without its artifact stays UNVERIFIED in project-state.json.
  • What happens on failure: critical review findings block task progress inside the session; a missing artifact blocks gate advancement in gate_engine.py as it does today.
  • Blocks a gate or needs human approval? Neither change is proposed: the gate engine keeps its current rules; Superpowers feeds it better evidence. Design sign-off and merge remain human decisions — matching Agency OS governance.
  • Smallest safe experiment: build one small internal tool with Superpowers in a scratch repo; copy its plan file, test commits, and review report into your project-state.json evidence format; then add one artifact-existence check to a copy of precommit_check.py on a test branch and observe. No gate-engine changes.

Daily Learning: subagent-driven development with fresh-context review

  • Concept (simple English): instead of one agent writing everything, a dispatcher sends each small task to a fresh subagent with no history, then a reviewer subagent inspects the result against the plan. Fresh eyes catch what invested authors miss; two-stage review checks spec compliance first, then code quality.
  • How an AI agent might get it wrong: the implementer subagent reports "task complete" without ever running the tests, or the reviewer rubber-stamps because the dispatcher shared its own optimistic summary instead of the actual diff.
  • How you recognize the failure: a "complete" task with no failing→passing test pair in git history; a review report that praises code that doesn't match the plan's file paths.
  • Which tool/test detects it: Superpowers' test-driven-development skill (deletes code written before tests) and verification-before-completion, plus git history inspection — and at the Agency OS level, the gate engine's existing evidence checks before QA advancement.
