Daily open-source discoveries for a one-person AI software agency
Report date: Friday, November 13, 2026 · Agency OS Edition · Addis Ababa (EAT)

Start Here (plain English)

The problem: when your coding agents each hold their own API keys and chat in private loops, two things go wrong at once. Security: one leaked prompt or log file exposes your real credentials. Governance: you cannot see what the agents said to each other, so you cannot audit or correct a decision mid-flight. A one-person agency needs agents that coordinate in a room you are always inside, with keys that agents never touch.

The solution in today's radar: AgentTeams, an Apache-2.0 collaborative multi-agent runtime platform: a Manager agent orchestrates a team of Worker agents (including the Hermes autonomous coding agent) inside self-hosted Matrix chat rooms that you can watch and interrupt at any moment, while an AI gateway holds all real credentials and hands Workers only scoped consumer tokens.

The Featured Factory: AgentTeams (Collaborative Multi-Agent Runtime Platform) TEST NOW

  • Link: github.com/agentscope-ai/AgentTeams · from the AgentScope open-source organization.
  • License (verified from the LICENSE file): Apache-2.0, "Copyright 2026 AgentTeams Contributors".
  • Verified repo facts (GitHub, Nov 13, 2026): 1,063 commits, 251 branches, 35 tags; latest commit Nov 13, 2026 (today) syncing docs for v1.2.7. Star count was not independently verified in this check, so none is quoted.
  • What it does (simple English): one command installs a full local stack: a Kubernetes-style control plane, a Manager agent (your "AI chief of staff"), a self-hosted Matrix chat server (Tuwunel) with the Element web client, an AI gateway (Higress), and MinIO shared file storage. You ask the Manager in the chat room: "Create a Worker named alice for frontend development", then "@alice implement a login page". Workers run in containers using different runtimes: OpenClaw (Node.js, general/skills), QwenPaw (Python, lightweight), Hermes (autonomous coding agent with terminal sandbox, self-improving skills, persistent memory), or an experimental DeepSeek Harness. Every message between you, the Manager and the Workers happens in the visible Matrix room; human interventions are audited, and tasks can be paused and resumed.
  • Recent verified change: v1.2.7 released Nov 12, 2026 (one-command startup and data-preserving upgrades, unified images for six Harness runtimes, expanded Tracing, Dashboard v1.4.1), plus commits on Nov 13, 2026. This is a new release of an established project, not a new project.
  • Why it matters to a vibe coder: it is the missing governance layer for agent teams: full visibility, audited human intervention, credential isolation, and declarative Worker/Team/Human resources you can treat as state — the closest open-source match to Agency OS's "human approval and evidence" principles at the coordination level.
  • Costs (verified status): the software is free (Apache-2.0). Real costs: one LLM API key (OpenAI-compatible, Qwen, DeepSeek and others supported), and machine resources — 2 CPU cores + 4 GB RAM minimum, 4 cores + 8 GB recommended for multiple Workers. A Kubernetes path (Helm) exists but is optional. Open source ≠ free model access.
  • Windows compatibility: documented and first-class — an official PowerShell installer (install.ps1, PowerShell 7+ recommended) alongside the macOS/Linux bash installer, with Docker Desktop/OrbStack/Podman as the engine; the v1.2.3 release notes even call out Windows AppService startup fixes. Windows status: plausible via the documented installer, UNTESTED on this PC.

Under Agency OS rules it complements gate_engine.py as the visible, auditable coordination room — it never replaces governance.

Honest Gaps

  • QA: no built-in test or verification stage; whether tests run at all depends on the Worker runtime and the skills you assign. This is the biggest gap for shipping production software.
  • SECURITY (code-level): the gateway protects credentials, but nothing scans generated code for vulnerabilities. A dedicated scanner such as Semgrep is the classic gap-filler, but it has not been verified or featured here — treat as a candidate to check separately.
  • ARCHITECTURE / SPECIFICATION: no formal artifacts (no PRD, no architecture doc); planning lives in chat messages and task state.
  • RELEASE/deployment: the pipeline ends at a PR posted in the room; nothing deploys.
  • Governance: no project-state file, no gate engine, no transition enforcement — visibility and audit, not lifecycle control.

Why It Fits Agency OS

  • Specialized agents coordinated by an orchestrator: a Manager agent directing role-specific Workers mirrors Agency OS's orchestrator-plus-specialists structure, with the twist that Workers can be different runtimes chosen per role.
  • Evidence before advancing: every exchange happens in a persistent, self-hosted Matrix room, and interventions, task state history and traces are recorded — the coordination equivalent of Agency OS's artifact-per-stage rule.
  • Human approval points: human-in-the-loop is the design default, not an option: you are in every room, interventions are audited, and tasks pause/resume under your control — directly aligned with CEO_REVIEW.
  • Living state: declarative Kubernetes-style Worker/Team/Human resources reconciled by a controller are the same idea as an authoritative project-state file, at infrastructure level.
  • Compatibility status: plausible, untested. Nothing in the docs shows it reads project-state.json or enforces lifecycle gates, so it complements gate_engine.py and never replaces it.

Limitations, Risks & Human Review

  • Fast-moving, enterprise-flavored project: 1,063 commits and six runtimes in under a year; contracts have had breaking changes (v1.1.1 declarative MCP resources). Pin a version (AGENTTEAMS_VERSION=v1.2.7) and read release notes before upgrading.
  • Alibaba/Aliyun ecosystem gravity: images default to a China-region registry (US and Southeast Asia mirrors are documented); some design docs are natively written in Chinese upstream. Expect some friction outside that ecosystem.
  • Resource footprint: the full stack (gateway, Matrix server, MinIO, controller, Manager, Workers) wants 4–8 GB RAM for multiple Workers; a modest laptop will feel it.
  • Agents with terminal sandboxes: Hermes Workers execute code autonomously. Keep them pointed at scratch workspaces; the gateway limits credential blast radius but does not sandbox what a Worker does inside its container.
  • Installer scripts piped to shell: curl | bash / iwr | iex run vendor code with Docker access. Review the script or pin a version if that bothers you.
  • No QA or release stage: never let a room "done" message count as QA evidence — that judgment stays in your gate engine and with you.
  • Windows: officially supported via the PowerShell installer (PowerShell 7+), but untested on this PC.

Agency OS Integration Proposal: AgentTeams as the visible coordination room in front of the gate engine

  • Problem solved: Agency OS agents coordinate in ways you cannot watch or interrupt; AgentTeams puts every agent-to-agent exchange in a room you inhabit, with audited interventions.
  • Workflow improved: after a gate passes, dispatch the approved task to a Worker from the room; when it reports done, the room transcript, task state history and traces become candidate gate evidence.
  • Lifecycle point: DEVELOPMENT coordination and CEO_REVIEW visibility; the audited-human-intervention log is the standout artifact for the CEO_REVIEW gate.
  • Inputs and outputs: an approved task description in; a room transcript, task state history, traces, and any PR the Worker produced out.
  • How results are validated: gate_engine.py treats the transcript and traces as candidate evidence only; QA evidence still comes from your own test runs, and a human confirms before any gate advances. A chat "done" is never sufficient evidence.
  • What happens on failure: pause the task, intervene (audited), or roll the gate back as usual; nothing auto-advances because an agent said so.
  • Gate or human approval: it feeds existing gates and replaces nothing (gate_engine.py, advance_gate.ps1 unchanged). CEO_REVIEW, scope changes, waivers, client acceptance and release stay human.
  • Smallest safe experiment: today's local install with one Worker and one scratch task; then decide whether the intervention audit log is worth exporting as CEO_REVIEW evidence. Zero changes to Agency OS scripts.

Daily Learning: "consumer tokens" — the credential failure mode of agent teams

  • Concept (simple English): in most agent setups, every agent holds a copy of your real API keys. AgentTeams inverts this: the gateway holds the real keys, and each Worker gets a scoped consumer token — so a leaked prompt, log or workspace exposes almost nothing.
  • How an AI agent might get it wrong: an agent given a full-privilege key echoes it into a log, a commit, or a message to another agent; or it "helpfully" shares credentials across rooms to unblock a teammate.
  • How you recognize the failure: agents that can call LLM/GitHub APIs directly rather than through a proxy; identical API keys in multiple agent configs; secrets appearing in transcripts or debug logs.
  • What detects it: a rule that Agency OS agents never hold raw provider keys — they call through a gateway or wrapper that logs every use, and gate checks that flag any key material appearing in artifacts or transcripts.
