The problem: your AI coding agents each live in their own window. Claude Code writes the code, another tool drafts the proposal, a third does research — and you are the glue: copying context between them, remembering where work stopped, and chasing every loose end. A one-person agency drowns in that glue work.

The solution in today's radar: Orkas-AI/Orkas is an open-source desktop app that puts a "Commander" agent in charge of a team. You give it a goal; it plans the steps, delegates each part to the right specialist agent (16 built-in), and can even drive the coding agents you already use — Claude Code, Codex, OpenCode — as local sessions under one plan. Projects hold the goal, rules, memory and files so work continues across days; to-dos and "Auto-advance" keep it moving; finished work always comes back for your review before anything leaves your machine.

Honest Gaps

  • No QA stage: no unit/integration/UAT verification loop — "done" can still be an agent's claim.
  • No SECURITY stage: nothing scans secrets, dependencies, authn/authz. Keep your own security stage and gate_engine checks.
  • No release/deployment stage: work stops at finished files on your disk.
  • No gate engine / governance: Auto-advance keeps moving without formal evidence gates — the exact problem gate_engine.py exists to solve. Orkas complements it, never replaces it.
  • Packaged app needs sign-in; the built-in model runs through Orkas's managed service. The source build has no account layer and can run fully offline against a local endpoint.
  • Third-party security flags: a third-party automated scan (SkillsLLM, July 2026) reported npm-audit warnings including high-severity hono and vite/launch-editor (Windows NTLMv2) issues — third-party, unverified; a reason to keep it off client-data machines until audited.

Why It Fits Agency OS

  • Commander = orchestrator; 16 specialists ≈ specialized agents — the same shape as Agency OS, as a running product.
  • Ask-before-send ≈ your human-approval rule: irreversible actions require explicit confirmation by default.
  • Local-first data, keys encrypted on disk ≈ your data-protection rule; with your own keys, model calls go straight from your machine to the provider.
  • Background reviews may conclude "nothing worth saving" ≈ your no-invented-facts rule — an agent may learn nothing rather than fabricate.
  • Projects with persistent memory and to-dos parallel project-state.json — philosophically aligned, never a substitute for the authoritative state file.
  • Structured records survive context compaction: file reads, changes and command executions are recorded durably — evidence, not memory.

Limitations, Risks & Human Review

  • Computer-on requirement: Auto-advance and automations only run while your PC is awake and Orkas is open — no server-side execution.
  • Cost creep: Auto-advance chains agent calls; the 500 free credits run out. Watch credit and provider usage before client work.
  • Auto-advance is semi-autonomous: keep it off for anything touching client data or connectors until you have observed it.
  • Third-party npm-audit flags (above) — human review required before adopting inside real client engagements.
  • CLI agents run with their own model settings and spend your Claude Code / Codex subscriptions.
  • Download from the official site only (orkas.ai) — several GitHub mirrors of this repo exist; use the official repo and download link.

Agency OS Integration Proposal: a DeepResearcher-fed DISCOVERY stage

  • Problem solved: discovery reports today depend on whatever the agent asserts; you want verified sources and flagged contradictions before writing project-state.json.
  • Workflow/agent improved: discovery + PM agents — feeding, never replacing, gate_engine.py.
  • Lifecycle stage: DISCOVERY → PROBLEM_DEFINITION.
  • Inputs: client goal + any client documents (added to Orkas's local Library — passages indexed in a local SQLite vector store). Outputs: an evidence-grounded discovery report with citations to source passages, feeding the PM agent's problem definition.
  • How results are validated: you open the cited passages yourself (Library citations link back to the source text); claims are marked VERIFIED only after you check them — matching your REAL/SIMULATED/ASSUMPTION discipline.
  • What happens on failure: unverifiable claims are marked UNVERIFIED and the gate does not advance to PROPOSAL — no evidence, no transition.
  • Gate or human approval? No gate is replaced; advancing to PROPOSAL still requires the gate engine plus your human approval.
  • Smallest safe experiment: one scratch project in Orkas, one DeepResearcher task, then manually copy its findings into a scratch project-state.json and check every citation yourself before marking anything VERIFIED.

Daily Learning: context compaction with structured records

  • Concept (simple English): when a long task outgrows the model's context, older messages are condensed — but Orkas keeps structured records of file reads, file changes and command executions that survive compaction, so key facts aren't lost.
  • How an AI agent might get it wrong: after compaction it "remembers" an earlier decision wrongly (or not at all) and quietly contradicts it — e.g., re-introducing a fix it had already ruled out.
  • How you recognize the failure: the agent contradicts an earlier instruction; it can't say where a fact came from; long runs drift from the goal.
  • What detects it: in Orkas, the surviving structured workspace records; in Agency OS, project-state.json as the authoritative record plus gate evidence checks — durable external state beats the agent's memory.
