Start Here (plain English)

The problem: a solo AI agency fails the same way every time — the coding agent starts writing code before anyone agrees on what is being built, and later "it runs" gets mistaken for "it's ready." What you need is not another toolbox; it's one connected pipeline where the agent must write down the spec, the plan and the tasks before touching code, and where each artifact can be checked by a human.

The solution in today's radar: one factory, one pipeline. GitHub Spec Kit installs slash commands into your AI coding agent that force a spec-driven workflow — constitution, specify, clarify, plan, tasks, implement, converge — with a human review point at every step.

The Featured Factory: GitHub Spec Kit TEST NOW

  • Link: github.com/github/spec-kit · official docs: github.github.com/spec-kit

  • What it does (simple English): a toolkit (Specify CLI + templates) that bootstraps spec-driven development inside your AI coding agent (Claude Code, Copilot, Cursor, Codex, OpenCode and others). Slash commands make the agent write a specification, a technical plan and a task list before it writes code.

  • Costs: MIT, free, no subscription for the toolkit. You still pay for your AI IDE/model access as usual — open source ≠ free model access. No hosting needed; templates are local.
  • Windows compatibility & installation (verified): works on Windows — v1.3.1 specifically fixed Windows PowerShell 5.1 and uv-on-Windows issues. Requires Python 3.11+ and the uv installer. No special hardware.

Spec Kit is the upstream half of a factory: problem definition through development and spec reconciliation. It complements gate_engine.py and never replaces it.

Honest Gaps

  • Not covered: security scanning (no dependency/secret/vuln checks), release/deployment automation, a persistent project-state authority, and a mechanical gate/rollback engine. Its templates and PowerShell scripts are helpers, not governance.
  • Gap-filler for security (external, verified separately): a scanner such as Trivy or Gitleaks run at the SECURITY stage remains necessary; Spec Kit does not add one.
  • Agency OS compatibility: plausible, untested — same philosophy (evidence before advancing, questions instead of assumptions), but no evidence yet that it integrates with project-state.json.

Why It Fits Agency OS

  • No invented facts: /speckit-clarify forces the agent to ask instead of assume — the same discipline as your REAL/SIMULATED/ASSUMPTION/VERIFIED/UNVERIFIED rules.
  • Evidence before advancing: every command produces a reviewable file (spec, plan, task list, checklist) that can be attached as gate evidence.
  • Constitution = governance rules: your non-negotiable Agency OS rules can be imported once per project and every later step is evaluated against them.
  • Human approval points: production guides recommend human gates at spec, plan and code review — matching your governance.

Limitations, Risks & Human Review

  • No security stage and no gate engine: never treat /speckit.implement output as production-ready.
  • Model/subscription costs: the toolkit is free; your AI IDE subscription is unchanged.
  • Never run specify init in a client repo without reviewing what it scaffolds; keep experiments in a scratch repo.
  • Don't grant the agent unrestricted machine access; review everything before running implement.

Daily Learning: "unit tests for English" (the /speckit.checklist idea)

  • Concept (simple English): before code, turn the spec into checkable statements ("only signed-in admins can delete records") so gaps in thinking surface as failing statements, not failing software.
  • How an AI agent might get it wrong: it writes the checklist from its own assumptions, so the checklist passes even when the spec was wrong — self-grading its own homework.
  • How you recognize the failure: checklist items that exactly mirror the spec wording, no challenge questions, everything green on the first pass.
  • What detects it: ask for one checklist item the spec does not answer; if none exists, the spec has blind spots. Agency OS rule: spec claims are UNVERIFIED until the clarify transcript and checklist artifacts exist.
