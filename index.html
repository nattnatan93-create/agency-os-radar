1. Octomind INVESTIGATE

  • Link: github.com/Muvon/octomind
  • What it does (simple English): an open-source coding agent and agent runtime in one Rust binary — "one binary, any model, MCP-native. Runs in terminal, CI, or as a daemon." Its distinctive idea: policy lives in TOML guardrails, not in approval prompts.
  • What changed recently (VERIFIED): new project trending Nov 3–4, 2026 (GitHub trending + 52 HN points per daily trackers; roughly 130–400 stars across snapshots — small but fast-moving). Active releases: 0.50.x → 0.51.1, including new tool-authorization control over agent actions.
  • Why it matters to a vibe coder: your governance lives in gate_engine.py and project-state.json; Octomind demonstrates the same principle — policy as code the agent reads before acting — inside the agent harness itself.
  • License & costs (verified): Apache-2.0 (verified from the LICENSE file today). Free code; you supply the model (any OpenAI-compatible key, or Octomind Cloud which is a paid service) — open source ≠ free model access.
  • Windows compatibility & installation: the README documents a PowerShell installer (irm .../install.ps1 | iex) — a remote script: review the source before running it, per your own safety rules. macOS/Linux have curl and Homebrew paths.
  • Agency OS fit / agent & stage: orchestrator / dev agent, DEVELOPMENT. Compatibility: plausible, untested.
  • Evidence/output: run records; the vendor's benchmark (24/25 tasks vs OpenCode's 19 at ~2× cost) is the author's own figure, not independently verified.
  • Limitations & risks: young project, small community, vendor-run benchmarks, curl-to-shell install pattern; human review of generated code stays mandatory.
  • Verdict: INVESTIGATE.

2. Betterleaks TEST NOW

  • Link: github.com/leaktk/betterleaks (README references the canonical org, betterleaks/betterleaks)
  • What it does (simple English): a fast, configurable secrets scanner — API keys, passwords, tokens — for filesystems, git repos, URLs and GitHub orgs. Maintained by the folks who made Gitleaks, including the original author.
  • What changed recently (VERIFIED): v2.0.0-rc.5 released Oct 28, 2026 (v1.9.0 was the Sep 29 stable); v2 stable looks close. Trending in security discussions Nov 3–4. Ships in MegaLinter; used by Aikido Security and others (per README).
  • Why it matters to a vibe coder: fast shipping is exactly how real keys land in git history. Betterleaks adds what Gitleaks lacked: validation (is the secret actually live?) and analysis (what identity and permissions does it grant?) — turning "we found something" into "here is the blast radius."
  • License & costs (verified): MIT (verified from the LICENSE file today). Free. Detection-only by default — no outbound requests unless you pass -v/-a. No subscription.
  • Windows compatibility & installation: verified paths: go install github.com/betterleaks/betterleaks/v2@latest (needs Go) or Docker (ghcr.io/betterleaks/betterleaks:latest); brew/dnf cover macOS/Linux. Prebuilt Windows binaries UNVERIFIED today.
  • Agency OS fit / agent & stage: security agent, SECURITY stage (secrets domain). Compatibility: plausible, untested with your scripts.
  • Evidence/output: findings with rule IDs, validation status and severity; exit codes your gate scripts can consume.
  • Limitations & risks: v2 is a release candidate; validation makes real HTTP requests to providers (deliberate, opt-in); revocation can destroy credentials — never run it without human approval.
  • Verdict: TEST NOW.

3. Worktrunk TEST NOW

  • Link: github.com/max-sixty/worktrunk
  • What it does (simple English): a Rust CLI that makes git worktrees as easy as branches, so several AI agents can work on the same repo at once without stomping each other's files. Three core commands, plus hooks and copy-on-write build caches.
  • What changed recently (VERIFIED): trending hard Nov 3–5 (~11.3k stars per a public directory snapshot; +438 in a day on Nov 4); the README carries a November 2026 note from the author on active maintenance.
  • Why it matters to a vibe coder: running discovery, dev and QA agents in parallel on one client project is the one-person agency's dream; worktrees are the safe, isolated way to do it — each agent gets its own checkout.
  • License & costs (verified): MIT OR Apache-2.0, your choice (verified from the LICENSE file today). Free, no external APIs, no subscription.
  • Windows compatibility & installation: verified: cargo install worktrunk (needs Rust), and a Winget package exists — installed as git-wt to avoid colliding with Windows Terminal's wt command.
  • Agency OS fit / agent & stage: orchestrator/dev/QA agents, DEVELOPMENT + QA. Compatibility: plausible, untested.
  • Evidence/output: isolated worktrees per branch; hooks can enforce precommit_check.py per worktree.
  • Limitations & risks: parallel work multiplies merge effort; keep project-state.json the single source of truth — two agents must never edit it from two worktrees without the gate engine mediating.
  • Verdict: TEST NOW.

5. NVIDIA Auto Ontology INVESTIGATE

  • Link: github.com/NVIDIA/auto-ontology
  • What it does (simple English): a Python framework that builds a semantic layer over business databases — it records what each metric means (e.g. which "revenue" is the real one) and serves it to agents through 9 read-only MCP tools, a CLI and a REST API. Agents get validated SQL with provenance instead of guessing from column names.
  • What changed recently (VERIFIED): released publicly and trending Nov 3–4, 2026 (3,130 stars, 263 HN points per daily trackers); part of NVIDIA's late-October Agent Knowledge Foundation announcement.
  • Why it matters to a vibe coder: small-business clients live in dashboards and reports; when an AI agent writes the SQL, wrong-but-valid SQL is the silent killer. This makes data definitions certified and machine-checkable.
  • License & costs (verified): Apache-2.0 (per repo LICENSE, confirmed by multiple sources) — but it defaults to NVIDIA NIM models and requires an NVIDIA API key (build.nvidia.com); accepts any OpenAI-compatible endpoint. Open source ≠ free inference.
  • Windows compatibility & installation: deploys via Docker Compose or Kubernetes/Helm — Docker Desktop on Windows can run the local stack; no native-Windows path documented. Hardware needs are meaningful (Postgres+pgvector, ingestion worker).
  • Agency OS fit / agent & stage: discovery/spec agents on data-heavy projects; REUSABLE_COMPONENT. Compatibility: untested.
  • Evidence/output: answers with SQL + provenance; check_readiness confirms a live certified layer before agents query.
  • Limitations & risks: heavy stack (Docker, Postgres, inference) for a one-person shop; NVIDIA's "90% faster ontology creation" is the vendor's own figure, not independently verified; no external contributions accepted.
  • Verdict: INVESTIGATE — revisit when a client project justifies the stack.

Test Today: Betterleaks on Windows (~20 minutes, no subscription)

  • Why this one: MIT, free, runs 100% locally, no API keys or model access needed, and produces exactly the evidence your SECURITY stage lacks.
  • Prerequisites: Windows PC with Go (go.dev) or Docker Desktop; ~500 MB free space. Internet only for install.
  • Official installation steps (from the README): go install github.com/betterleaks/betterleaks/v2@latest — or docker pull ghcr.io/betterleaks/betterleaks:latest.
  • Practical test: in a scratch git repo you own, plant a well-known fake key (e.g. AKIAIOSFODNN7EXAMPLE — the AWS docs example, never a real one) plus a realistic DB_PASSWORD=.... Then run betterleaks fs . and betterleaks git . (full history). Do not add -v/-a in the first run — detection-only is the safe default.
  • Expected results: both planted secrets flagged with rule IDs and severity; a clean exit code on a clean folder. That output is your SECURITY-stage evidence.
  • Safety precautions: scan only code you own; never validate (-v) credentials you don't control — it contacts the provider; never run revocation; keep reports private (they describe weaknesses).

Daily Learning: detection vs validation of secrets

  • Concept (simple English): a scanner detects that a string looks like a key (pattern/entropy). Validation checks with the provider whether it still works. Detection is safe and offline; validation is a live network request that reveals what the credential can do.
  • How an AI agent might get it wrong: it declares "this leaked key is critical!" (no validation — maybe it's revoked) or "that finding is a false positive" (no evidence), or worse, runs validation/revocation on credentials it doesn't own.
  • How you recognize the failure: a severity claim with no validation status or scan artifact behind it; unauthorized outbound validation attempts in logs.
  • What detects it: Betterleaks' detection-only default plus opt-in validation — the artifact shows which stage produced each claim. Agency OS rule: security claims are UNVERIFIED until a scan artifact exists.
