Start Here (plain English)

The problem: for a vibe coder, the hardest question before shipping to a client is not "does it run?" or "do tests pass?" but "is this actually secure?" AI-written code can look clean and still leak secrets, trust user input, or break authorization. A single prompt asking your agent to "check security" produces one guess at a time, with no coverage and no proof.

The solution in today's radar: cloudflare/security-audit-skill. Cloudflare open-sourced the agent skill that seeded its own internal vulnerability discovery harness. It turns the coding agent you already use (Claude Code, Codex, Cursor, others) into a disciplined six-phase security auditor: it maps the codebase, assigns isolated hunter agents from a coverage ledger, forces a different agent to try to disprove every finding, and writes machine-readable results (findings.json) validated by schema-checking scripts. Nothing is "confirmed" until an independent verifier failed to knock it down.

  • Unverified: precision/false-positive rates, token cost per run, and best-performing models are not published by Cloudflare.

Why It Fits Agency OS

  • Adversarial validation: the agent that checks a finding is never the agent that found it, the same separation your evidence rules demand before anything advances.
  • needs_validation, not fake certainty: a lead that cannot be proven keeps its exact unresolved fact and gets no severity, your UNVERIFIED/BLOCKED discipline, built in.
  • Machine-readable evidence: findings.json is schema-validated by deterministic scripts (validate-findings.cjs, validate-coverage-ledger.cjs), so a gate can consume it without trusting prose.
  • Severity requires impact: likelihood × impact, not deviation from a checklist, and a missing second layer of defense is a hardening note, not a vulnerability. No inflated findings.
  • Additive coverage ledger: repeated runs target gaps and revalidate changed source instead of starting over, the same way project-state.json carries evidence forward.

Limitations, Risks & Human Review

  • Token-heavy on large codebases; use guidance mode for focused questions and budget caps where your agent supports them; Cloudflare publishes no cost figures.
  • Without an OS-enforced sandbox, the skill keeps execution-dependent leads as needs_validation instead of running target code, which is the safe default, but it means dynamic vulnerabilities stay unproven unless you sandbox.
  • It does not replace dependency/secret scanners or your QA gate; a clean audit is necessary, never sufficient, and a project is not production-ready because the audit came back clean.
  • Few commits and no tagged releases: pin the exact commit you install; review the skill's prompt files before pointing them at client code.
  • Human review required: every confirmed finding needs a human read before client or release decisions; needs_validation items are open questions, not evidence of security.

Daily Learning: adversarial validation ("the agent that checks a finding is never the agent that found it")

  • Concept (simple English): an agent that discovers a bug is invested in it; it tends to confirm its own discovery. Adversarial validation hands each candidate to a fresh agent whose only job is to disprove it, so only findings that survive a hostile check are reported as real.
  • How an AI agent might get it wrong: it "verifies" its own finding in the same session, recycling its own reasoning as proof, so a hallucinated vulnerability gets labeled confirmed, or a real one gets waved away.
  • How you recognize the failure: the finding and its confirmation come from one context (no separate verifier transcript), the confirmation restates the claim instead of testing it, or no needs_validation/rejected records exist at all (a red flag: nothing was ever disproven).
  • What detects it: the skill's Phase 3/5 structure plus its deterministic validators; under Agency OS rules, any security claim without an independent verifier's output stays UNVERIFIED, and the SECURITY gate stays BLOCKED.
